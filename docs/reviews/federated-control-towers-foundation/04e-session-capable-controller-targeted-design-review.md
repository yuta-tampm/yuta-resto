## Proposed exact positive production path

1. **Controller and owner.** Keep the existing PowerShell `state-helper.ps1` process as the sole transaction controller and `FileShare.None` lock owner. Propose exactly one new repository executable at `.agents/skills/yuta-federated-control-towers/scripts/browser-observer.mjs` as a child browser adapter. The child does not own activation state or the context lock. Its script bytes and direct dependency are pinned by reviewed artifacts and rehashed at invocation. Caller input may specify a reviewed decision ID; it cannot choose the adapter path, browser executable, target identity or trusted observation payload.
2. **Runtime dependency.** Add a direct root runtime dependency on `playwright-core@1.51.1` to `package.json` and `pnpm-lock.yaml` only after separate Tasks/TIC and Apply authorization. The installed transitive copy is discovery evidence, not a dependency owner. The adapter uses Node `>=24.17.0` and Playwright's Chrome channel. No provider API, CDP debug listener or new service is proposed. Chrome 154 compatibility with Playwright 1.51.1 and ChatGPT login is a focused implementation acceptance risk; if it fails, do not substitute a different package/version/browser without reviewed scope.
3. **Authentication.** For each live selection attempt, the adapter launches a dedicated headed Chrome instance with one non-persistent `browser.newContext()` and downloads disabled. A Human signs in directly in that browser window if needed; YUTA never receives a password or MFA secret, calls `cookies()`/`storageState()`, or writes a persistent `userDataDir`, HAR, video, trace or screenshot. Authentication is a bounded preflight while the parent holds the context lock, before Human authority consumption and before any protocol send. If login is unavailable, cancelled, expired or ambiguous, the parent durably stops non-executing; it does not consume selection authority or send a probe. The session is lost when the context/browser closes; a new attempt requires fresh Human sign-in. Temporary browser-process data and crash cleanup remain Sensitive Design review items; no session artifact belongs in YUTA authority state.
4. **Direct trusted invocation.** The parent starts the fixed child script with `ProcessStartInfo` and private redirected stdin/stdout handles, validates the child exit/status and accepts exactly one bounded observation object directly from that child pipe. A caller-supplied JSON line, `CODEX_CUA_ACTUAL_UI`, nonce or hash is never provenance. The adapter obtains live URL and DOM-derived protocol evidence from its own Playwright page; it does not accept those values as input. The parent verifies the child script hash, process identity, strict output schema, target/run/epoch/probe binding and durable journal state. The child cannot commit activation or write the authority journal.
5. **Target and protocol.** The child navigates only to the reviewed exact `https://chatgpt.com/g/<PROJECT_ID>/c/<CONVERSATION_ID>` URL from the typed selection decision, checks current canonical URL, Project path and conversation ID, plus visible title as a secondary check, and rejects redirects to login, another Project or another conversation. After authentication and target preflight, the parent validates and durably consumes the exact unused `LIVE_TOWER_SELECTION` proof, writes `AUTHORITY_CONSUMED`, read-backs, records activation and probe intent, then instructs the child to perform one fresh read-only handshake→valid command→bound result→tower evaluation round using the reserved `RUN_ID` and `COMMAND_ID`. No prose, partial response, second block, mismatch or old result is executable. The child reports only attributable completion or uncertainty through its direct pipe. `ACTIVE_COMMIT` requires both the consumed Human proof and a fresh valid observation; neither alone suffices.
6. **Continuous lock and durability.** The PowerShell process acquires the exact context lock before state reconciliation and browser launch. It retains the same open handle through Human login preflight, proof verification and consumption, child invocation, protocol observation, journaled probe outcome or uncertain stop, activation snapshot replacement/read-back, and final result. It releases the handle only after durable state convergence. A competing process cannot acquire the lock during the child call. A timeout never resends or reuses the decision. On parent crash, the OS releases the handle but the accepted intent and consumed proof remain; restart reconciliation blocks activation/replay. An orphan child may finish at most its original read-only send, cannot write `ACTIVE`, and must stop when its parent pipe closes; its existence cannot clear uncertainty. Later tests must exercise this exact crash window.

The proposed child observation schema is a closed object: `SCHEMA_VERSION`, `PROTOCOL_VERSION`, `PROBE_TRANSACTION_ID`, `EXECUTION_CONTEXT_ID`, `CAUSAL_LINEAGE_ID`, `TARGET_RUN_ID`, `ROUND_ID`, `COMMAND_ID`, `ACTIVATION_EPOCH`, `PROJECT_ID`, `CONVERSATION_ID`, `CANONICAL_URL`, bounded `VISIBLE_TITLE`, `OBSERVED_AT_UTC`, `BROWSER_PROCESS_ID`, `RESULT_CLASS` (`COMPLETE`, `DELIVERY_UNCERTAIN`, `EXECUTION_UNCERTAIN`, `SESSION_LOST`, `TARGET_MISMATCH`), and hash of the observed complete protocol result when `COMPLETE`. Unknown, missing, duplicate, stale or conflicting fields block. The controller derives all expected identities independently from the reviewed decision and durable state; the child merely reports what it directly observed. Neither child stdout nor observation hash is Human approval.

## Failure, privacy and authority boundaries

Browser executable missing, profile/context unavailable, login failure, target not open, wrong Project/conversation/title, malformed or incomplete protocol, child crash, timeout, parent crash, state-write/read-back failure, or uncertain message delivery all leave no new executable tower. Before proof consumption, stop with unused authority and no probe send. After consumption or probe intent, persist attributable stop or uncertainty under the same lock; if persistence fails, restart reconciliation treats the pending state as uncertain and blocks. Never resend solely after timeout/reload, rerun the same `COMMAND_ID`, reconsume the Human decision, reset budgets, or activate from browser observation alone. Fencing, handoff and fresh-run rules from the approved Design stay in force.

The Node child can technically access browser session material, so it becomes a sensitive trusted implementation owner. The reviewed code must prohibit cookie/storage APIs, page-content export and arbitrary navigation; run under the current user without privilege elevation or public debug port. Only exact target IDs/URL/title, bounded timing, outcome and hashes enter the existing journal/snapshot. No transcript, full DOM, customer/private Page Chat content, credential, token, cookie or session is persisted. The browser context closes on success, stop and process exit; orphan handling and any OS temporary-profile remnants need explicit Sensitive Design and later tests. PAGE_LOCAL Product/shaping remains with the owning Page Chat; Global escalation stays Workflow v3. This architecture gives no Product authority, Apply authorization or Human Gate approval to the browser adapter.
