## Security invariants under review

The sole live-selection authority chain is `PRE_DECISION_DESCRIPTOR -> accepted HUMAN_GATE_RESULT -> ACCEPTED_GATE_RESULT_RECORD -> APPROVAL_RECORD -> SEMANTIC_DECISION_RECORD -> CONSUMED_AUTHORITY_PROOF_V1`. The helper reads and validates it; a caller-created `CURRENT_USER` or `DECISION_SOURCE` string, generic `AUTHORIZATION_REFERENCE`, free-form approval prose, synthetic probe, title, or handoff cannot substitute for any link. This uses workflow-governed repository provenance; it does not claim cryptographic Human attestation.

`DECISION_TYPE: LIVE_TOWER_SELECTION` binds exact execution context and reviewed causal lineage; `DECISION_SCOPE` uses `BUDGET_TYPE: NONE` and `BUCKET_KEY: NONE` without granting budget. Its exact typed payload binds intended action, current source record hash/state/epoch, target activation epoch and fresh run, structured Page/Global role/scope/owner tuple, exact tower instance, Project/conversation/title/URL, and preserved reviewed selection artifact path/hash. `DECISION_ID` is SHA-256 of canonical type, scope and payload before the Human Gate. The later activation command carries it but independently obeys the command ledger. No future `COMMAND_ID` is required to obtain approval; no postapproval substitution can retain the same valid ID and matching chain. A path/hash alone does not prove Product classification or Page owner.

The private token mapping moves to version 2 solely to add `LIVE_TOWER_SELECTION -> APPROVE_LIVE_TOWER_SELECTION`. The original three version-1 mappings and their meanings remain unchanged. The accepted `RESULT_CORE_V1` requires `STATUS: COMPLETED`, the exact token and bound decision item, run, round, command, lineage, stage, review packet preapproval hash and scope. Version 1 cannot authorize this new decision; generic or normalized tokens cannot either. The accepted-result record remains the machine-readable result source.

The existing eight-field `CONSUMED_AUTHORITY_PROOF_V1`, complete `AUTHORITY_CONSUMED` journal `STATE_PAYLOAD`, hash/revision verification and lock transaction suffice without new top-level activation, handoff, proof or journal fields. The proof binds `DECISION_ID`, `DECISION_TYPE`, `DECISION_ITEM_ID`, `RESULT_HASH`, `APPROVAL_RECORD_ID`/hash and semantic-record hash. Under the exclusive lock, durable journal flush/read-back commits consumption; complete snapshot replacement/read-back follows before activation. Consumption appends exactly one proof and does not grant `ACTIVE`, alter budgets/freezes or select a different target. Duplicate decision, item, result, approval or proof cannot authorize another activation.

`ACTIVE` requires both a consumed selection proof for this transaction and successful fresh read-only live target/probe evidence. Neither condition alone suffices. The source and selected target, role, owner, context, instance, Project, conversation, epoch and `TARGET_RUN_ID` must still match at the actual transition. Old `ACTIVE` authority is fenced and terminal before a replacement can become `ACTIVE`; D2's `FileShare.None` lock must span the authority-critical browser transaction, including observed result and durable outcome. Page or Global rotation and Page-to-Global escalation each require a new decision and fresh run; handoff transfers state/proofs but does not authorize the receiver. A Page proof cannot be used for Global or a different Page. PAGE_LOCAL Product/shaping authority remains with the owning Page Chat.

## Residual risk and implementation evidence required later

This model adds no signatures, external identity provider, signed transcript, remote attestation or distributed lock. It assumes every executor for one context uses the same supported Windows/NTFS checkout and long-lived helper lock; that assumption must be tested, not inferred from this packet. Human-reviewed Page owner/classification and target content remain outside helper judgment. A browser interruption may leave delivery or execution uncertain and stop work despite a valid prior Human selection. This is deliberate fail-closed behavior.
