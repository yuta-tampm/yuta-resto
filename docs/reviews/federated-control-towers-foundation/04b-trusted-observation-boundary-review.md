## Minimum positive-path contract for targeted design review

The reviewer must identify an actually callable production observation mechanism and its implementation owner. The trusted component must itself invoke the selected browser/UI capability, bind exact Project/conversation, context, lineage, tower instance, target run, epoch and probe transaction, and keep caller-provided target parameters separate from an internally sourced observation. Raw stdin, unsigned JSON, source labels and hashes remain informational data. They cannot select the production adapter or satisfy the `ACTIVE` join.

The same authority-critical transaction must acquire and continuously hold the existing FileShare.None context lock before selection-proof consumption, target setup and observation. It must persist the accepted decision proof, probe intent, attributable result or uncertainty, and snapshot convergence before release. A second process cannot commit authority during that interval. If the browser operation occurs outside PowerShell, the Design must specify how a long-lived helper/owner securely retains that lock across the external call and prevents arbitrary callers from feeding the return channel. Independent helper calls with separate lock acquisitions do not satisfy RC2.

`ACTIVE_COMMIT` must require both the exact consumed `LIVE_TOWER_SELECTION` Human proof and a fresh actual observation from the reviewed path. Missing, stale, wrong target, replayed, lost delivery, uncertain execution or ambiguous crash recovery blocks; there is no automatic resend or reconsumption. Handoff/rotation preserves ledger, budgets, freezes, proof ancestry and lineage. SelfTest uses isolated `FED-QA-*` state and cannot inject production provenance. Only bounded IDs, state, references and hashes may persist; no transcript, customer data, credential, token, cookie, session or private Page Chat content.
