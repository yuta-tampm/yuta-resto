## Decisions

### 1. App-owned closed policy và server-owned configuration

Thêm pure `apps/backoffice/src/lib/backoffice-exposure.ts` cho type `BackofficeExposureProfile = 'internal' | 'release-a'`, closed product/support/static path predicates và shared A attention status set `NEW/TO_PROCESS/DRAFTED/FOLLOW_UP`. Module không đọc env, không DB/framework authority và không tự cấp grants. Presentation có thể nhận server-selected profile để lọc menu/UI; browser prop không được sử dụng như server authority.

Server-only `src/server/backoffice-exposure.ts` đọc/validate `BACKOFFICE_EXPOSURE_PROFILE` bằng Zod ở request boundary. Explicit `internal` và `release-a` hợp lệ. Unset ở development/test giữ current internal behavior; unset ở production hoặc bất kỳ invalid value fail closed. Không đọc query/cookie/form/header cho selection, không `NEXT_PUBLIC_*`, không top-level evaluation khiến build cần DB/config và không persist profile vào tenant data. Environment choice có hiệu lực cho toàn process/instance, không tùy user/establishment. Server helper cung cấp invoked-capability/page availability guards và Google-only repository options.

Closed A product paths: `/`, `/aujourdhui`, exact basic-profile path, exact Integrations và Users & Access paths, Avis root và một detail segment. Existing `/parametres/restaurant` chỉ là basic-profile redirect alias. Auth/recovery paths là exact current connexion/password-reset/establishment-resolution/selection/no-establishment routes. Exact current Google OAuth start/callback routes tiếp tục existing server checks. Static exemptions chỉ framework static/image resources và current public presentation files; không generic extension bypass, wildcard API hoặc broad product prefixes. Unknown product/API paths fail closed trong A. Existing legacy redirects phải có permitted destination hoặc bounded unavailable recovery; không phụ thuộc redirect ordering để bảo vệ data.

Alternative: tenant entitlements/role mutations hoặc generic feature-flag package sẽ trộn availability với authorization và thêm owner/store; không cần cho whole-instance selection. Client-only hiding không bảo vệ direct entry.

### 2. Transport guard cộng invoked-capability guard

Mở rộng existing Next `src/proxy.ts`, giữ named proxy và Pointage CSP/referrer/no-store/security behavior. Matcher bao phủ request paths trừ cần thiết framework static resources; policy có closed exemptions như trên. Invalid required selection trả safe 503, no-store, không expose env details. Trong A, GET deferred product paths redirect về `/aujourdhui?exposure=unavailable`; denied API/non-GET trả safe unavailable trước body/provider/data effects. Pointage APIs giữ typed `{ code: 'POINTAGE_ACCESS_DENIED' }` 403 và security/no-store headers để stale client clear đúng lifecycle. Invalid config dùng typed Pointage unavailable 503. Không copy trusted-profile headers hoặc serialize incoming credentials/cookies vào override metadata.

Proxy chỉ admission; không thay actual server enforcement. `requireAuthenticatedTenant` kiểm tra server-owned invoked return path trước session/metadata/deferred repository reads. Existing Booking, Personnel, Formalités và Satisfaction actions/helpers dùng các deferred paths nên bị chặn ngay cả khi Next-Action được POST tới allowed URL. Inventory có 34 non-Knowledge deferred exports (Booking 9, Personnel 19, Formalités 5, Satisfaction 1). Registry development-only early safe-unavailable response vẫn không được read/mutate; availability guard được đặt trước branch nếu cần consistent disposition. Không thay permission evaluator.

Tám exported Knowledge mutations thêm explicit `restaurant-knowledge` availability guard trước context/input operation. Knowledge loaders cũng không được gọi trong A; shared profile route không là capability authority. Allowed Reputation/basic-profile/user administration/tenant switching/login/logout actions giữ existing trusted guards. `safeReturnTo` giữ local-URL validation, và trong A chỉ giữ allowed product destinations/query; deferred hoặc malformed destination về Today. Context selection/switching dùng cùng function; query không cấp source/scope. Availability denial qua action dùng safe permitted redirect/standard unavailable response, không trả protected target facts.

Pointage page và `handlePointageRawClockingRequest` enforce server availability trước bootstrap/admission/body/credential processing cho cả bảy operations: context, identify, state, clock-in, clock-out, recover, end. Internal vẫn giữ exact synthetic/test DB/origin/address/runtime prerequisites. Không issue/end continuation, replay/recover receipt hoặc create clock events trong A. Existing client `end()` đã clear local generation, continuation, pending intent/timers/state trước best-effort server end và không claim ACK; giữ behavior này. Denied end không cần cũng không được giả server invalidation commit; successful prior reset/invalidation remains effective. Không thay independent credential/grant evaluation.

Alternative: layout-only guard không bảo vệ public Pointage/APIs, placeholder routes hoặc action replay trên allowed URL. Dynamic action-ID allowlist phụ thuộc build metadata và không cần khi owning action boundary biết capability.

### 3. Google/source và queue được enforce trong cloud repository

Mở rộng existing Reputation repository APIs bằng trusted optional options, không thêm transport-schema/browser authority: `requiredSource?: 'GOOGLE'` cho detail/status/draft/note; list options cho status set và source constraint. A caller luôn truyền server-derived Google restriction, kể cả parse failure/fallback. `query.source` không được override `requiredSource`. Internal caller không options giữ existing supported behavior.

`listFeedback` áp dụng organization, establishment, STAFF assignment, forced source và optional status-set trong same WHERE cho list/total. A counters dùng cùng selected WHERE; thêm local `attentionCount` aggregate bằng accepted status set, giữ existing legacy counters và internal semantics. Không sử dụng absence of PUBLISHED reply làm A attention predicate. Pagination cap chỉ preview/page, không count. `queue=attention` trong Avis là presentation filter mapped phía server tới fixed shared set; thêm query.status/search/rating có thể thu hẹp nhưng không widen set/source/actor scope. Today query source Google + same set; `newCount` vẫn là NEW, toàn bộ NEW nằm trong attention set. Default Avis hiển thị all permitted Google rows; attention link mở queue với same base scope.

`findFeedbackDetail` đặt requiredSource trong parent query trước full row/child read. Missing/DIRECT/foreign/unassigned parent trả same unavailable/not-found. Replies/notes child queries thêm organization predicate và verified scoped parent ID; child không có establishment column, parent supplies that scope. Các affected mutations chọn scoped/source parent trong transaction trước effect, giữ STAFF visibility; bounded parent locking nếu cần giữ assignment/source predicate tới mutation. Final parent writes có org/est/source predicates và kiểm tra affected row trước success audit. Child reply lookup/update có org + verified parent + child ID; không ID-only writes. Note chỉ insert sau scoped parent admission. Không đổi owners, columns, events hoặc public feedback writes. No note/reply/status/success audit khi denied. Internal Google-only draft vẫn giữ current SOURCE_NOT_SUPPORTED semantics; A disallowed source trả generic not-found.

Alternative: đọc row rồi lọc tại UI/action vẫn đọc deferred DIRECT detail và dễ divergence. Repo-wide auth/query refactor không cần; chỉ touched Reputation functions và tests.
