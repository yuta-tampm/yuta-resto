## Why QA is blocked

The normal browser session and the fresh `U6M4` recovery run exposed posted messages, response generation, and completed responses; neither produced a genuine `DELIVERY_UNCERTAIN` state or positive proof of pre-post non-delivery. The approved delivery rule forbids resending because of a timeout or absence of response. The conditional `U6M4` reload was not performed. A later reload after a completed terminal response preserved the exact conversation identity and posted history. In `U9T4`, one reload during visible response generation also preserved the posted handshake and same conversation; the response resumed and completed without resend or partial-command execution. Delivery remained certain because the handshake was visibly posted. Network disable, logout, or browser crash was not induced. No safe observable failure path in this session proved the uncertainty branch end to end.

The Human then identified one real Page Chat by exact URL. In `P7K2`, Control Tower reported an unsuccessful exact-source lookup through its available context surface and refused to substitute similar conversations. The observed `UNKNOWN` disposition and refusal to invent missing decisions satisfy only case 21. No actual page-specific Product or shaping context was retrieved, so cases 18–20 remain partial and no real Page Chat repository/context comparison was possible. Codex did not access Page Chats directly, preserving Workflow v3 authority. A separate wrong-title home tab and an ambiguous Project overview without a selected conversation ID both failed the exact target preflight; no message was sent there. `M6R2` and `P3L7` proved live rejection of the remaining malformed-command variants and a retransmitted accepted command. Delivery uncertainty, full recovery, and real Page Chat routing remain unproved. These required gaps prevent QA PASS; see [`case-matrix.md`](case-matrix.md).

Safe bounded recovery consisted of checking the same selected target before sends, waiting for each response to complete, checking posted-message visibility and exact copied block text, and using fresh RUN_IDs after terminal actions. The missing environment state and exact Page Chat content were not obtained. A future QA session needs a safe observable delivery-failure setup and a Page Chat context source Control Tower can actually access, with provenance, without Codex opening the Page Chat. It must preserve the same target, authority, at-most-once, and no-resend rules.

The current bridge skill file no longer matches the hash-bound owner candidate used by historical formal VERIFY. The continued browser probes demonstrate only the behaviors they observed; they do not revalidate the changed skill file or promote current-candidate technical readiness.
